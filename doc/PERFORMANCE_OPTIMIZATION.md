## 合成性能对比

使用源码运行，全部为生成的数据，不读取小说正文或插件持久化数据。每项先预热 3 次，再记录 21 次；中位数为第 11 个样本，P95 为第 20 个样本。服务测试运行于 Windows / Node.js v24.14.1；浏览器测试运行于本机 Chromium 155。

| 场景 | 优化前中位数 / P95 | 优化后中位数 / P95 | 重复工作变化 |
| --- | --- | --- | --- |
| 时间线：500 章、500 关联 | 412.301 / 424.359 ms | 1.458 / 1.753 ms | 索引构建 500 → 1 次 |
| 伏笔：500 章、500 来源 | 402.576 / 409.153 ms | 1.365 / 1.556 ms | 索引构建 500 → 1 次 |
| 排序：1000 章固定种子乱序 | 10.079 / 10.943 ms | 1.163 / 1.367 ms | 章节号解析 34,572 → 1,000 次 |
| 统计：47,318 字符相同文本连续 20 次 | 35.918 / 38.085 ms | 1.763 / 1.911 ms | Markdown 清理 20 → 1 次；两者结果均为 23,114 字 |
| 轨迹：500 列、100 设定行 | 813.4 / 1402.2 ms | 48.4 / 55.4 ms | 单元格 50,500 → 1,000；另有 101 个行背景 |

轨迹场景的全部 DOM 元素从 52,105 个降到 2,706 个，减少约 94.8%；两者总高度均为 7555.05px。浏览器另对浅色/深色、0.5/1/2 倍缩放的六种组合比较了行标题、事件的位置和尺寸，全部一致，包括由多段文本撑高的行。

服务测试隔离了章节枚举、伏笔文件读盘和解析，测量重点是引用映射、排序与统计本身；轨迹测量包括清理旧容器、设置样式、创建 DOM 以及强制布局。浏览器使用真实渲染器与 CSS，并提供最小 Obsidian API 替身。这些结果用于复现计算量与布局开销的变化，不能直接推算真实 Obsidian 的整体启动、输入延迟、峰值内存或手机性能；本轮未测量这些指标。

复测命令（仓库根目录）：

```powershell
node scripts/performance-benchmark.cjs
node scripts/performance-benchmark.cjs --browser
```

第二条命令仅监听 `127.0.0.1:18765`。在浏览器打开输出地址，分别点击几何对比和性能测试按钮；结束后用 Ctrl+C 停止。可在命令最后传入其他本地基线 ref。测量时不要并行运行构建或测试，避免竞争 CPU。
